# Именованные диалоги и сводка последних сообщений

Дата: 12 октября 2026 года

## Цель

Пользователь должен однозначно понимать, с кем открыт личный диалог, видеть в списке чатов последнее сообщение и время либо дату его отправки, а также получать новый диалог автоматически после входящего сообщения. Нажатие на имя или аватар собеседника должно открывать профиль правильного пользователя.

Успешный сценарий: пользователь A отправляет сообщение пользователю B; сообщение сохраняется один раз, у обоих появляется один и тот же диалог, B сразу видит его в списке с правильным именем A, текстом и временем, а внутри чата отображаются оба сообщения в хронологическом порядке с датой и временем.

## Подтверждённые ограничения

- Изменение охватывает ASP.NET API, SignalR и .NET MAUI-клиент.
- Источником истины остаётся сервер и существующая реляционная БД.
- Новая таблица сводок чатов не создаётся: необходимые данные уже хранятся в пользователях, контактах, участниках чатов и сообщениях.
- Личный чат содержит двух участников. Групповой чат сохраняет собственные название и аватар.
- Сквозное шифрование не добавляется. Тело последнего сообщения расшифровывается существующим серверным механизмом перед формированием ответа API.
- Push-уведомления FCM и APNs не используются; обновление активного приложения выполняется через SignalR.

## Выбранный подход

API возвращает полноценную серверную сводку чата: данные собеседника и последнее сообщение. MAUI не выполняет отдельные запросы для каждого элемента списка. Это исключает N+1-запросы, гарантирует единые правила формирования имени и позволяет серверу корректно учитывать локальные имена контактов.

Рассмотренные альтернативы:

1. Клиент самостоятельно загружает участников, профили и сообщения. Подход отклонён из-за большого числа запросов, мерцания списка и дублирования правил между платформами.
2. Отдельная денормализованная таблица сводок. Подход отклонён как преждевременный: текущие объёмы не требуют дополнительной модели согласованности и миграции БД.

## Контракт API

`ChatResponse` расширяется двумя вложенными объектами:

```csharp
public sealed record ChatPeerResponse(
    Guid UserId,
    string DisplayName,
    string? AvatarObjectId);

public sealed record ChatLastMessageResponse(
    Guid Id,
    Guid SenderUserId,
    string Type,
    string? Body,
    DateTimeOffset CreatedAt,
    DateTimeOffset? DeletedAt);
```

В `ChatResponse` добавляются:

```csharp
ChatPeerResponse? Peer,
ChatLastMessageResponse? LastMessage
```

Для личного чата `Peer` содержит другого участника. Для группового чата `Peer` равен `null`, а клиент использует `Title` и `AvatarObjectId` самого чата. `LastMessage` равен `null`, если сообщений ещё нет.

Расширенная форма возвращается всеми существующими операциями, отдающими чат, включая список, получение одного чата и создание личного либо группового чата. Отдельные клиентские запросы профиля для построения списка не нужны.

### Правило отображаемого имени

Сервер выбирает имя собеседника в следующем порядке:

1. локальное имя контакта, сохранённое текущим пользователем;
2. имя и фамилия из профиля;
3. username;
4. номер телефона;
5. строка `Пользователь`.

Локальное имя принадлежит владельцу списка контактов и не изменяет профиль собеседника или отображение имени у других пользователей.

### Последнее сообщение

Последним считается доступное участнику сообщение с максимальной последовательностью в чате. Сервер возвращает открытый текст через существующий механизм защиты сообщений, а не зашифрованное значение из БД.

Представление в MAUI:

- обычный текст — текст сообщения;
- изображение — `Фото`;
- видео — `Видео`;
- аудио или голосовое сообщение — `Аудио`;
- прочее вложение — `Файл`;
- удалённое сообщение — `Сообщение удалено`;
- исходящее сообщение получает префикс `Вы:`.

## Сохранение и восстановление диалогов

Сообщение сначала сохраняется в БД в существующем личном чате и только после успешной транзакции публикуется через SignalR. Отправка не создаёт второй диалог между той же парой пользователей.

Если активный участник личного чата ранее скрыл диалог, новое сообщение снимает у него признак скрытия, и диалог снова появляется в списке. Это применяется к адресату входящего личного сообщения. Правило не возвращает участников, покинувших групповой чат, и не добавляет новых участников в группу.

Список чатов всегда строится из сохранённых серверных данных. Поэтому вход с другого устройства или перезапуск приложения показывает те же диалоги и сообщения.

## Обновление через SignalR

После фиксации сообщения сервер публикует существующее событие создания сообщения. Открытый экран чата продолжает синхронизировать сообщения по этому событию.

Экран списка чатов при получении события запрашивает обновлённый `ChatResponse` только для затронутого чата, затем:

1. добавляет карточку, если диалога ещё не было в локальном списке;
2. обновляет имя, аватар, последнее сообщение и его время;
3. перемещает чат на верх списка.

После переподключения SignalR клиент полностью перечитывает список чатов, чтобы восстановить события, пропущенные во время отсутствия соединения. Ошибка точечного обновления не удаляет текущие данные: клиент сохраняет имеющуюся карточку и повторно синхронизируется при следующем открытии страницы или переподключении.

## Интерфейс MAUI

Карточка личного диалога показывает `Peer.DisplayName` и `Peer.AvatarObjectId`. Карточка группы показывает собственные название и аватар.

Под последним сообщением отображается:

- `HH:mm`, если сообщение отправлено сегодня по локальному времени устройства;
- `dd.MM.yy`, если сообщение отправлено раньше;
- ничего, если сообщений ещё нет.

Внутри чата каждое сообщение показывает `dd.MM.yyyy HH:mm` по локальному времени устройства.

Заголовок личного чата использует данные `Peer`. Нажатие на имя или аватар открывает существующий экран профиля пользователя по `Peer.UserId`. У группы такое нажатие не должно ошибочно открывать профиль одного из участников.

## Ошибки и согласованность

- SignalR не является подтверждением сохранения: событие отправляется только после успешной записи сообщения.
- Повторная доставка события не создаёт дубликат сообщения или карточку чата; клиент обновляет элементы по идентификаторам.
- Если профиль заполнен частично, сервер применяет определённую цепочку резервных значений имени.
- Если последнее сообщение недоступно или повреждено, API не должен делать весь список чатов недоступным; для превью возвращается безопасное значение `Сообщение` и ошибка журналируется без раскрытия содержимого.
- API не возвращает номера телефонов или профили посторонних пользователей через `Peer`: собеседник определяется только среди активных участников конкретного личного чата.

## Изменения компонентов

### ASP.NET

- Контракты чата: добавить `Peer` и `LastMessage`.
- Сервис/хранилище чатов: одним серверным запросом либо ограниченным набором пакетных запросов получить собеседников, локальные имена контактов и последние сообщения без клиентского N+1.
- Операция отправки сообщения: после сохранения восстановить скрытый личный диалог адресата и затем отправить SignalR-событие.
- Swagger: автоматически показать новые поля и их описания в схемах ответов.

### .NET MAUI

- Модель карточки чата: использовать серверные `Peer` и `LastMessage`.
- Список чатов: формировать превью и дату по утверждённым правилам, выполнять upsert и сортировку после SignalR-события.
- Экран чата: показывать полную дату и время сообщения.
- Заголовок личного чата: переходить в профиль по `Peer.UserId`.

## Проверка

### Серверные тесты

- личный чат возвращает другого пользователя как `Peer`;
- локальное имя контакта имеет приоритет над профилем, username и телефоном;
- групповой чат возвращает `Peer = null` и собственное название;
- возвращается последнее по последовательности сообщение с расшифрованным телом;
- скрытый личный диалог адресата восстанавливается после нового сообщения;
- новое сообщение не создаёт второй чат между той же парой;
- участник, покинувший группу, не возвращается автоматически.

### Клиентские тесты

- заголовок и карточка используют имя и идентификатор собеседника;
- текст, медиа, удалённое и исходящее сообщения получают правильное превью;
- сегодняшнее сообщение форматируется как `HH:mm`, более старое — как `dd.MM.yy`;
- внутри чата выводится `dd.MM.yyyy HH:mm`;
- повторное SignalR-событие обновляет существующую карточку без дубликата;
- новый чат добавляется и перемещается наверх.

### Сквозная ручная проверка

1. Войти как `+79089260075` и отправить сообщение пользователю `+79512723576`.
2. Войти как `+79512723576` без ручного создания чата.
3. Убедиться, что диалог появился, показывает правильное имя отправителя, последнее сообщение и время либо дату.
4. Открыть диалог и убедиться, что новое и ранее существовавшее сообщения отображаются по порядку с датой и временем.
5. Нажать на имя или аватар и убедиться, что открыт профиль пользователя `+79089260075`.
6. Повторить отправку после скрытия диалога у получателя и убедиться, что диалог автоматически вернулся в список.

## Вне объёма изменения

- переработка визуального дизайна экранов;
- push-уведомления в фоне;
- сквозное шифрование;
- новая модель удаления сообщений;
- объединение уже существующих ошибочно созданных дублирующихся личных чатов;
- миграция или очистка тестовых данных.
